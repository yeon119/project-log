# 프로젝트 중간보고 — 웹 발표자료

12페이지로 구성한 웹 발표자료입니다. 흰 배경과 검은 글씨 중심이며, 외부 라이브러리나 인터넷 연결 없이 실행할 수 있습니다.

## 실행
이 폴더의 index.html을 Chrome 또는 Edge로 여세요.
index.html, style.css, app.js, assets 폴더를 함께 보관해야 합니다.

## 조작
- 다음: 오른쪽 방향키 / PageDown / Space / 다음 버튼
- 이전: 왼쪽 방향키 / PageUp / 이전 버튼
- 처음·마지막: Home / End
- 전체 화면: F 또는 전체 화면 버튼. 미지원 시 F11
- 목차: G 또는 목차 버튼
- 참고 설명: N 또는 설명 버튼
- 사진: 클릭하면 원본 확대. Escape로 닫기
- 모바일: 좌우 스와이프, 긴 페이지는 세로 스크롤
- URL 끝의 #6처럼 번호로 특정 페이지에 바로 접근 가능

설명 기능은 같은 화면에 표시됩니다. 발표 중 열면 청중에게도 보이며, 비공개 발표자 모드가 아닙니다.
공개 파일에는 참고 설명도 포함되어 있습니다.

## GitHub Pages
1. ZIP을 압축 해제합니다.
2. 이 폴더의 내용물을 저장소에 업로드합니다. 저장소 루트에 index.html이 오도록 합니다.
3. 저장소 Settings → Pages에서 브랜치 게시 방식과 업로드한 브랜치, /(root)를 선택합니다.
4. 배포 후 GitHub가 표시하는 URL을 확인합니다.
계정·저장소 환경에 따라 Pages 제공 여부나 메뉴가 다를 수 있습니다.

모든 파일 경로는 상대 경로이므로 프로젝트 저장소의 하위 URL에서도 사용 가능합니다.
저장소 생성·업로드·공개 배포는 아직 수행하지 않았습니다.

## 수정 위치
- index.html: 각 section.slide가 한 페이지입니다. 본문과 참고 설명 수정
- style.css: 글자 크기, 배치, 반응형 스타일
- app.js: 페이지 이동, 목차, 전체 화면, 사진 확대
- assets: 첨부 이미지 원본

## 내용 구성
1. 프로젝트 중간보고 (제목만)
2. 차례
3. 프로젝트 배경
4. 최종 구현 목표
5. 시스템 구성과 동작 흐름
6. 개발 진행 현황 (3~7주차 기반 기능 5단계 / 전체 7단계)
7. 접근제어와 차단 기록 수집 (4~5주차)
8. 로그 분석과 데이터베이스 관리 (5~7주차)
9. 자동 저장과 백업 운영 (6~7주차)
10. 남은 개발 영역
11. 최종 테스트 방법
12. 감사합니다

## 사실 구분
- 자동화·요청량 기반 방어는 검토 단계입니다.
- 등록 정보·공개 키·VPN 주소 연결 관리는 향후 목표입니다. 진행도 5/7은 발표용 작업 단계 기준이며 전체 완성률이 아닙니다.
- 60건은 실습 당시 저장 로그 수이며 접속 횟수가 아닙니다.
- WireGuard 사진의 핸드셰이크는 이전 통신 기록입니다.
- 7페이지는 접근 조건을 표로 설명하고, 실제 nftables forward 규칙 사진을 함께 보여줍니다.
- 일일 백업은 예약 등록 확인 단계입니다.
- 사진은 6·7페이지에만 사용합니다.

## 제작 시 검증 범위
페이지 수, 목차 대상, 이미지 경로, JavaScript 문법을 검사했습니다.
제작 환경의 브라우저 제한으로 실제 화면·전체 화면·터치 동작의 최종 검증은 완료하지 못했습니다.
발표 전에 Chrome 또는 Edge에서 전체 화면으로 한 번 확인해 주세요.
