기기와 권한의 연결

기기 정보 → 공개 키·VPN 주소 → 허용 서비스

관리자 웹 화면에 연결할 DB와 터미널 관리 기능을 구현했습니다.

기존에는 특정 VPN 주소에서 내부 웹 서버의 80번 포트로 접근하도록 방화벽에 직접 설정했습니다. 이번에는 그 주소가 어떤 기기에 연결되어 있는지, 그 기기에 어떤 서비스를 허용할 것인지 DB에서 관리하는 것이 목표입니다. 아직 관리자 웹 페이지를 만든 것은 아닙니다. 먼저 화면 뒤에서 사용할 등록과 조회 기능을 터미널 프로그램으로 구현했습니다.

기기 등록과 중복 방지

등록한 기기

Windows-Lab-PC

기기 ID client-001
관리 상태 active

검증 결과

재실행해도 한 번만 등록

첫 실행: 기기 등록 완료
두 번째 실행: 기존 정보 유지

active는 DB의 관리 상태이며, 실시간 VPN 연결 여부를 뜻하지 않습니다.

첫 번째로 Windows 실습 PC를 client-001이라는 기기 ID로 등록했습니다. ID는 관리용 식별자이고, Windows-Lab-PC는 사람이 알아보기 위한 이름입니다. 같은 명령을 다시 실행해 중복 등록이 발생하지 않는지도 확인했습니다. 화면처럼 두 번째 실행에서는 기존 정보를 유지합니다. 여기서 active는 DB에 저장된 관리 상태입니다. 실제 VPN이 현재 연결되어 있다는 의미는 아니며, 통신 여부는 WireGuard에서 별도로 확인합니다.

실제 설정과 확인

Gateway에 등록된 peer 공개 키와
Windows 인터페이스 공개 키가 일치

연결 등록 및 동일 정보 중복 방지 확인

현재 연결의 중복 방지

기기 · 공개 키 · VPN 주소별
종료되지 않은 연결의 중복 제한

종료 시각이 비어 있으면 현재 연결

이력 저장 구조와 최초 등록 완료 · 키 교체·주소 재할당 절차는 이후 구현

다음으로 등록한 기기를 실제 WireGuard 통신 상대와 연결했습니다. Gateway에 등록된 공개 키와 Windows 화면의 공개 키가 일치하는지 확인하고, VPN 주소 10.40.0.2와 함께 DB에 저장했습니다. 현재 연결에서는 같은 공개 키나 주소를 중복 등록할 수 없도록 했습니다. 연결 종료 시각도 저장할 수 있도록 설계했지만, 주소 변경과 재할당 기능 자체는 아직 만들지 않았습니다. 공개 키는 키를 가진 VPN 상대를 확인하는 수단이고, 사람의 로그인 인증은 별도 기능입니다.
10주차 / 06

기기별 접근 정책 통합 조회

기기출발지 VPN 주소목적지허용 서비스
client-00110.40.0.210.30.0.10TCP 80

활성 기기 + 현재 VPN 연결 + 활성 정책을 JOIN으로 조회

DB 정책의 중복 등록 방지와 현재 nftables 허용 조건의 일치도 확인했습니다.

접근 정책에는 client-001이 내부 서버 10.30.0.10의 TCP 80번 포트에 접근할 수 있다는 조건을 등록했습니다. 같은 조건을 다시 등록해도 중복되지 않도록 했습니다. 이어서 SQL JOIN으로 기기 정보와 VPN 주소, 접근 정책을 연결해 조회했습니다. 활성 기기이면서 종료되지 않은 VPN 연결과 활성 정책만 조회합니다. 이렇게 얻은 결과가 현재 nftables에 설정된 출발지와 목적지, 포트 조건과 일치하는 것도 확인했습니다.
10주차 / 07

DB 정책을 방화벽 규칙으로 변환

DB 조회→주소·프로토콜·포트 검사→규칙 문장 생성
iifname "wg0" oifname "ens34"
ip saddr 10.40.0.2 ip daddr 10.30.0.10
tcp dport 80 ct state new counter accept

규칙 생성·출력까지 검증했습니다. 실제 방화벽에는 적용하지 않았습니다.

조회한 정책을 nftables가 이해하는 규칙 문장으로 바꾸는 프로그램도 만들었습니다. 먼저 IPv4 주소와 프로토콜, 포트 값이 올바른지 검사합니다. 이후 현재 실습 환경의 wg0와 ens34 인터페이스를 포함해 새 연결 허용 규칙을 생성합니다. 출력 결과는 기존 허용 규칙과 같은 조건입니다. 다만 이것은 전체 방화벽 설정이 아니라 허용 규칙 한 부분의 미리보기입니다. 기존 연결 응답 허용과 기본 차단, 로그 규칙은 별도로 필요하며, 아직 실제 적용이나 nft 문법 검사는 진행하지 않았습니다.
